# Development Delta 664cde8 to 0b4af2e

Parent: [[16 - Development Implementation Snapshot]]

This note records the two commits that landed on `development` while the full implementation audit was in progress. The core runtime architecture did not change; local infrastructure, feature-pipeline integration and configuration were improved.

Compare: [664cde8...0b4af2e](https://github.com/adnanelhabashy/the-eye-v2/compare/664cde8f30e9a2b5731520c394097d38d6262cae...0b4af2e99e530ce56a94d894865c761b7d7306e8)

## Commit 26f1008e

Message: `feat: implement CSV feature generation scenario and dynamic dataset configuration in integration script with supporting documentation.`

Implemented changes:

- new `docs/synthetic-data-feature-pipeline.md`;
- feature-archive integration supports `FEATURE_ARCHIVE_CASE`, `FEATURE_ARCHIVE_CONFIG`, `FEATURE_ARCHIVE_CASE_FILE`;
- dynamic selection of circular, circular-training, spoofing-training or custom synthetic config;
- standalone CSV feature-generation scenario;
- integration assertions tolerate datasets not generated by a selected scenario instead of assuming every dataset directory always exists;
- documented commands for generate -> publish -> collect -> verify -> label ML datasets.

## Commit 0b4af2e9

Message: `at this point all should be working`

Implemented changes:

- API appsettings explicitly allow both `http://127.0.0.1:5173` and `http://localhost:5173` for Galaxy Web CORS;
- new `docker-compose.kafka.yml` with Kafka `3.9.0` KRaft, host listeners on `9092` and `29092`, and Kafka UI on `8085`;
- local PostgreSQL connection/documentation normalized from database `theeye_orleans` to `theeye`;
- feature-writer PostgreSQL registration test updated to `theeye`;
- persistence/feature archive operational docs and scripts normalized to `theeye`;
- feature archive integration host launch fixed so compiled DLLs start from their own output directory and therefore load the copied `appsettings.json`;
- this specifically resolves the earlier harness problem where three circular feature datasets were missing because `FeatureStore:Datasets` settings were silently dropped.
